## 🐛 v5.100 修复：多远程下 `p` 假报"没有任何变更，无需推送"

**现象**：项目同时绑定 GitHub(`origin`) 与 CNB(`cnb`) 时，用 `p cnb` 推送后
再按 `p`，提示"没有任何变更，无需推送"，而 GitHub 上仍是旧版。

**根因**：`p` 用当前分支上游 `@{u}` 判断是否需要推送：
```bash
ahead=$(git rev-list --count "@{u}..HEAD" ...)
[ "$ahead" -gt 0 ] && push || echo "没有任何变更，无需推送"   # 直接 return
```
当 `branch.<分支>.remote` 指向 `cnb` 时，`@{u}` = `cnb/分支`；
本地与 cnb 已一致 → `ahead` 恒为 0 → 假报"无需推送"**直接返回，
`git push origin` 从未执行**，GitHub 永远停在旧版。
（实测 jian_box：本地 HEAD 与 cnb/dev 相同，GitHub 的 origin/dev 落后 1 个提交。）

**同源问题（一并修复）**：
1. `p cnb` 首推不建立上游 → `@{u}` 为空 → `git rev-list` 失败被吞 → 同样假报"无需推送"。
2. `p "备注"` 被当成远程名 → 报"远程未绑定"（v5.97 引入远程名参数时踩坏）。
3. 推送兜底 `git push -u "$远程"` 无条件改写上游，把 origin 静默换成 cnb，加深问题 1。
4. `_fz_unrelated_history_guide` 硬编码 `origin`，`p cnb` 撞上 unrelated histories 时会操作错误远程。

**修复**：
- 判断/落后检测基准改为**本次目标远程** `$_fz_remote/$分支`，`fetch` 也改到该远程。
- 首推（远程尚无该分支）→ 显式 `git push -u` 建立跟踪；已有上游绝不改写。
- 参数解析判定第一个非选项参数是否为**已绑定远程名**，否则当备注；支持 `-r/-m`。
- 推完目标远程后，其他仍落后的远程仅提示 `📡 远程 [cnb] 还落后 N 个提交`。
