## 一、整体架构

```
~/.bashrc
   └── source <仓库>/fz-tools/fzgit.sh          ← 唯一的挂载点
          ├── 环境变量（FZ_VERSION / FZ_BASE / FZ_MAIN / FZ_TOOLS_DIR）
          ├── core.sh                            ← 通用工具（校验/摘要/转义/.gitignore）
          ├── modules/*.sh                       ← 15 个功能模块（自动加载）
          └── 别名注册（c / p / st / f / rsx …）  ← 用户实际敲的指令
```

**关键点**：模块被 `source` 进你的**当前交互 shell**，不是子进程。所以：

- 模块里**绝不能出现 `set -e`**（会让整个终端在任一命令失败时退出）
- `cd` 会真实改变你的当前目录（这是 `c` 导航能工作的原理）
- 函数内改动环境变量会污染当前会话，需要 `export` 时谨慎

## 二、状态存放位置（唯一真相源）

理解这套脚本的核心：**没有隐藏状态，全部落盘在固定文件**。

| 状态 | 文件 | 格式 |
|---|---|---|
| 书签 | `~/.fz_bookmarks` | 每行 `名称\|绝对路径` |
| AI 备注配置（可选） | `~/.fz_ai.conf` | `key=value` 三行，权限 600 |
| 版本号 | `fz-tools/fzgit.sh` 内 `FZ_VERSION="5.x"` | 由 `bash version.sh bump` 显式递增 |
| 其他所有 git 状态（分支/远程/提交） | 项目自己的 `.git/` | 原生 git |

> ⚠️ **凭据一律不放仓库内**：`fz-tools/fzgit.sh` 被 git 追踪，
> 而 `p` 会执行 `git add .`。把 Key 写进去＝一次推送即公开泄漏
> （历史版本正是这么干的，现已修复）。`p` 在提交前会扫描暂存区，
> 命中疑似凭据即中止。

**因此**：换设备只要同步仓库 + 重建书签即可；删掉 `~/.fz_bookmarks` 等于重置导航（不会动任何代码）。

## 三、首次安装流程

```
1. pkg install git curl gh
2. git clone https://github.com/zzgs219G/scripts.git
3. 写入 ~/.bashrc（幂等，重复执行不堆叠）：
      sed -i '/fz-tools\/fzgit.sh/d' ~/.bashrc
      echo 'source "$HOME/scripts/fz-tools/fzgit.sh"' >> ~/.bashrc
      source ~/.bashrc
4. setup   →  检查环境 + 配置 git 用户名/邮箱 + 首次书签引导
5. ghlogin →  登录 GitHub（可选，但 cl/repo/rls 需要）
6. aikey   →  配置 AI commit Key（可选）
```

旧版 curl 注入用户改跑 `bash fz-tools/install.sh`，会自动迁移 AI Key 并清理旧注入块。

## 四、日常主流程：找项目 → 改 → 存

这是 90% 的使用场景。

```
    c                    （书签 → 项目 → 进入）
    │
    ▼
  ┌──────────────────────────────────────────┐
  │ 阶段1：书签选择                            │
  │   ↑/↓ 移动 · 回车确认 · 数字直选           │
  │   [＋ 添加新书签] [q 退出]                 │
  └──────────────────┬───────────────────────┘
                     ▼
  ┌──────────────────────────────────────────┐
  │ 阶段2：项目列表（该目录下的一级子目录）      │
  │   [📂 进入此目录] = 原 [0]，进书签根目录    │
  │   ✓ 标记 = 该目录是 git 仓库               │
  │   [↩ 返回书签选择] = 原 [b]                │
  └──────────────────┬───────────────────────┘
                     ▼
  ┌──────────────────────────────────────────┐
  │ 阶段3：项目操作                            │
  │   [1] 进入项目（回车默认）                  │
  │   [2] 移动到其他书签（剪切）                │
  │   [3] 复制到其他书签（保留原件）             │
  └──────────────────┬───────────────────────┘
                     ▼
              进入后自动打印 _git_status_summary
              （分支 / 变更数 / 领先落后 / 最近提交）
                     ▼
              改代码 …… 然后 st → p
```

**快捷通道**：`c <关键字>` 直接跳过阶段1
- 命中书签名 → 进阶段2
- 命中项目名（模糊匹配，不区分大小写）→ 直接 `cd` 进去

### 进入项目后看状态

```
st
```
输出含：书签名 / 分支 / 变更文件数 / 领先落后 / 最近提交 / 远程地址 / 提交数与追踪文件数，
以及**逐条列出改了哪些文件**（按 新增／修改／删除／未跟踪 分组）。

需要贡献者、标签数等更全的信息时用 `info`。

## 五、保存流程：p 推送（防冲突是核心）

`p` 不是简单 `git add . && git push`。完整决策链：

```
                          p
                          │
                          ▼
              解析参数：远程名 / skip / "备注"
                 （不是已绑定的远程名 → 当备注）
                          │
                          ▼
              在书签项目内吗？──── 否 ──→ 询问「是否继续」
                          │是                    │否 → 结束
                          ▼                      ▼
              git fetch <目标远程>（只读，不碰本地）
                          │
                          ▼
              目标远程有该分支吗？──── 无 ──→ 首推
                          │有
                          ▼
              本地落后远程吗？
                    │
              ┌─────┴──────┐
             否            是
              │            │
              │            ▼
              │     ⚠️ 列出远程新提交 + 涉及文件 + 本地未提交数
              │            │
              │      ┌─────┼─────────┐
              │    [1]拉取  [2]强推   [3]取消
              │      │        │(二次确认)  │
              │      ▼        ▼          ▼
              │   _pull_now  --force-   结束
              │      │      with-lease
              └──────┴────────┘
                          │
                          ▼
              有本地变更吗？──── 无 ──→ 判断是否有未推送提交
                    │有              │
                    ▼                ▼
        _git_auto_ignore      有 → 直接推
        显示变更文件清单        无 → 报「已是最新」
                    │
                    ▼
        生成 commit message
          ├─ 有 AI Key → 请求 Anthropic，展示建议，可改
          ├─ 有备注参数 → 直接用
          └─ 都没有 → 默认 "⚡ update: 月-日 时:分"，可改
                    │
                    ▼
          （仅当推送目标是自己这个 scripts 仓库时）
          FZ_VERSION 自动递增为 <主版本>.<提交数+1>
                    │
                    ▼
              git commit + git push
                    │
                    ▼
          推送成功 → 仅当当前分支尚无上游时建立跟踪
                    （已有上游绝不改写，避免 origin 被静默换成 cnb）
                    ▼
          提示其他仍落后的远程（不自动推）
```

### 判断"是否需要 push"的基准

**是本次目标远程的该分支，不是 `@{u}`**。一个项目可能同时绑多个远程
（如 `origin`=GitHub、`cnb`=CNB），而上游只指向其中一个；用 `@{u}` 判断
会对另一个远程看错对象，导致假报「无需推送」而实际从未推送。

原因：多远程场景下（origin=GitHub，cnb=CNB，且上游指向 cnb），
旧版用 `@{u}` 判断会恒为 ahead=0 → 假报"没有任何变更，无需推送"并 return，
GitHub 永远停在旧版。这是真实发生过的 bug。

### 常见失败路径

| 现象 | 脚本行为 |
|---|---|
| 远程有无关历史（首推撞上自动生成的 README） | 自动识别 `unrelated histories`，给出修复引导 |
| 本地落后远程 | 自动执行 `_pull_now` 后重试推送 |
| 凭据失效 / 分支保护 / 网络 | 列出三种常见原因，指明下一步指令 |

## 六、炼化流程：f 打包源码给 AI

```
      f [选项] [关键词]
        │
        ├── 无参数      全量：全部源码
        ├── -d          增量：只打包未提交改动 + 未跟踪新文件
        ├── <关键词>    定向：只打包路径含关键词的文件（f nav）
        └── -h          帮助
        │
        ▼
  扫描（_f_burn_scan）
    白名单扩展名：kt/kts/java/py/go/rs/js/ts/vue/xml/md/yaml/sh…
    黑名单排除：.git/ .gradle/ build/ node_modules/ bin/ out/
                *.lock / *-lock.json / *.min.js
                *.keystore *.jks *.key *.pem google-services.json
                res/ 与 assets/ 下的 json/xml（资源瘦身）
        │
        ▼
  逐文件处理
    ├─ .kt/.kts → 状态机剥离注释（行内 // 也剥离，字符串/URL 不误伤）
    │              同时剥离 import → 记入依赖清单
    └─ 其他     → 去首尾空白 + 删空行
        │
        ▼
  写入头部四段结构
    1. 仓库概览      目录树（maxdepth 3）
    2. 源码结构树    自动探测 */src/main/{java,kotlin}/*，按包层级折叠计数
    3. 入口表        Application / Activity / ViewModel / Singleton
    4. 符号索引      TYPE/FUN/VAL → 文件:行号（行号是源文件真实行号）
        │
        ▼
  末尾附「依赖汇总」：被剥离的 import 去重列出（仅供 AI 参考）
        │
        ▼
  输出 code_<项目名>[_diff][_<关键词>].txt
    路径优先级：项目根上一级 > 第一个书签 > FZ_BASE > HOME
    然后尝试复制该路径到剪贴板（带 3 秒超时，失败不影响结果）
```

### 已知陷阱

- **剪贴板阻塞**：装了 termux-api 但没装 Termux:API 应用时，
  `termux-clipboard-set` 会永久阻塞。已加 `timeout 3` 兜底。
- **大文件**：>64KB 不丢弃，完整打包并标注大小。
- **中文标识符**：正则用排除法 `[^[:space:]({<:]+` 而非白名单，中文类名/函数名完整保留。

## 七、多远程与多平台

```
remote
  │
  ├── [1] origin（p 的默认目标）
  ├── [2] 新建远程（cnb / gitee / upstream…）
  ├── [3] 删除远程（列表选择，不再手打名字）
  └── [4] 查看远程详情
        │
        ▼
   绑定方式二选一
   ├── 📎 粘贴完整 URL（任意平台，自动识别）← 推荐
   └── 🔤 用户名/仓库名 + 平台 拼装
            平台表：GitHub / GitLab / Gitee / 腾讯云 CNB / CODING / 自定义
            用户名默认取 gh 登录账号，仓库名默认取当前目录名
```

**推送语义**：一条指令推一个远程。`p` = origin，`p cnb` = 推 CNB。
推完会给其他落后远程**提示但不自动推**，避免误以为"推一次全平台同步"。

## 八、异常与恢复流程

| 场景 | 处理 |
|---|---|
| 推送被拒（本地落后） | `p` 内部自动诊断 → 引导 `_pull_now` → 重试 |
| 推送被拒（无关历史） | 自动识别并给出 `--allow-unrelated-histories` 引导 |
| 合并冲突 | `fix` 列出冲突文件 → 选一个用 nano 打开 → 手改 → `git add` → `p` |
| 切分支前想保住改动 | `save` → 切 → 回来 `pop` |
| 撤销工作区改动 | `undo`（⚠️ 不可恢复） |
| 取消暂存 | `unstage` |
| 撤回最后一次提交 | `no`（代码保留，只撤提交记录） |
| 拉取失败（有本地改动） | `_pull_now` 会先询问是否继续；冲突则转 `fix` |

**回滚原则**：所有会破坏数据的操作（强推、覆盖、合并）都有二次确认，
且默认选项永远是"取消"。

## 十、改动本仓库的约定

来自 `AGENTS.md`，供后续维护者（或 AI）遵守：

1. **不要在模块里用 `set -e`**——模块运行在用户交互 shell 内。
2. **`$PREFIX` 必须校验**——非 Termux 环境该变量为空，直接拼 `/bin/` 会写到系统根。
3. **新增模块**：在 `fz-tools/modules/` 建文件 → 加到 `fzgit.sh` 的 `_fz_mod` 加载列表
   → 注册别名 → 同步 `h all` 菜单与 `README.md`。
4. **改完必须跑**：`bash -n <改动文件>` + `bash fz-tools/smoke-test.sh`（期望 45 通过 / 0 失败）。
5. **破坏性操作默认取消**，且要有二次确认。
6. **失败信息要能指导下一步**，不能只说"失败了"。

### 版本号

`FZ_VERSION` 在 `fz-tools/fzgit.sh` 顶部。推送本仓库时由 `p` 自动递增为
`<主版本>.<提交数+1>`，**不要手改**。
