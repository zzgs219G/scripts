
《burn.sh (焚诀) 脚本架构重构与瘦身工程计划书》
文档版本：v6.0-Plan
执行对象：Coding Agent / Bash 脚本开发者
运行环境：Termux (Android) / Linux Bash 4.0+ / Git
核心目标：彻底解决源码打包体积膨胀、AI 上下文被垃圾 Token 撑爆的问题；增加骨架提取（Skeleton）、模块精准过滤与 Git 改动定向打包模式。
模块一：重构目标与需求拆解
1.1 核心痛点
 * 垃圾 Token 泛滥：旧脚本仅过滤了少量 lock 文件，大量 Android/Web 矢量图（res/drawable/*.xml 动辄数千行 path 坐标）、assets/ 密文、release.properties 敏感密钥均被打包。
 * 缺乏场景分级：做“架构规划”和做“具体代码修改”对上下文的需求完全不同，现有脚本只有一刀切的全部 dump。
 * 剪贴板与兼容性：输出路径与剪贴板依赖单一命令，缺少跨平台/无 Termux 环境时的优雅降级。
1.2 功能模式矩阵（CLI 接口契约）
| 命令形式 | 模式名称 | 核心行为 | 预期产物体积 |
|---|---|---|---|
| f | 智能全量模式 | 过滤所有资源、矢量图、敏感文件后的核心源码打包 | 减少 50%~70% |
| f -s / f --skeleton | 骨架计划模式 | 仅保留项目树 + 类/接口声明 + 数据模型 + 函数签名，折叠实现体 | 减少 85%~95% (出计划书专用) |
| f -d / f --diff | 增量改动模式 | 仅打包 git status / git diff 涉及的未提交或最新修改文件 | 极小 (局部微调专用) |
| f <module_keyword> | 定向模块模式 | 仅打包匹配路径关键词的文件（支持组合如 f -s tools） | 按需精准 |
模块二：核心架构与流水线设计
[CLI 参数解析] ──> [确定模式: FULL / SKELETON / DIFF] ──> [确定目标模块]
                            │
                            ▼
[项目树 & 元数据生成] (注入 Header + maxdepth 3 目录概览)
                            │
                            ▼
[文件扫描引擎] (git ls-files / find + 扩展名白名单 + 深度黑名单过滤)
                            │
                            ▼
[内容处理管道] ──┬──> (Skeleton 模式): Awk 抽取 Class/Interface/Fun 签名
                 └──> (Full / Diff 模式): Sed 清理空白行与行尾空格
                            │
                            ▼
[输出与反馈] (写入临时文件 ──> 原子覆盖目标路径 ──> 复制路径/内容到剪贴板)

模块三：详细执行任务清单 (Agent 任务分解)
Task 1: 参数解析与模式分发器
 * 任务目标：支持 -s / --skeleton、-d / --diff、-h / --help 以及位置参数 [MODULE] 的任意组合解析。
 * 技术要求：
   * 使用 while [ $# -gt 0 ] 循环解析。
   * 支持 f -s navigation 这种“模式+模块”的复合调用。
Task 2: 过滤规则引擎（多层黑白名单）
 * 任务目标：重写文件扫描管道，精准拦截无用/敏感/体积过大文件。
 * 白名单规则（允许打包的源码后缀）：
   * html|htm|js|jsx|ts|tsx|vue|astro|svelte|css|scss|less|json|md|kt|kts|java|xml|py|rb|go|rs|swift|dart|yaml|yml|sh|bash|php|c|cpp|h|hpp|cs|lua|sql|proto|toml|gradle|properties
 * 黑名单规则（必须强行排除的路径与文件）：
   * 构建与依赖：.git/, .gradle/, .idea/, build/, node_modules/, dist/, bin/, out/
   * 锁与生成物：*lock*, *.min.js, *.min.css
   * 敏感凭据：release.properties, *.keystore, *.jks, *.key, *.pem, google-services.json
   * 静态体积杀手：
     * res/drawable.*/.*\.xml（矢量图 path 坐标拦截）
     * res/mipmap.*/
     * assets/.*\.(json|bin|dat|wasm|txt)（大配置/字库/离线包拦截）
   * 单文件体积硬门限：跳过超过 64KB 的非核心源码文件。
Task 3: 骨架抽取器（Skeleton Extractor）
 * 任务目标：实现 -s 模式下的代码压缩逻辑，仅保留结构。
 * 实现方案：
   * 通过 awk 匹配关键语法关键字：
     * 包与引用：package, import
     * 结构体与模型：data class, class, interface, enum, sealed, object, typealias, struct
     * 签名与注解：@Composable, @Serializable, fun ..., override fun ..., val ..., var ...
   * 将函数内部实现体折叠为 { ... }。
Task 4: 增量模式（Git Diff Extractor）
 * 任务目标：实现 -d 模式，用于排查 Bug 或局部功能 review。
 * 实现方案：
   * 扫描源替换为：git diff --name-only HEAD + git ls-files --others --exclude-standard。
Task 5: 目录树注入与多平台剪贴板增强
 * 任务目标：
   * 产物头部自动注入精简目录树（find . -maxdepth 3），让 AI 在只读几页代码时就能理解整个项目的目录组织。
   * 剪贴板支持：优先 termux-clipboard-set，兜底 xclip / wl-copy / pbcopy。
模块四：验收标准
 * 功能验证：
   * 运行 f：产物排除所有 res/drawable/*.xml 和 release.properties。
   * 运行 f -s：产物体积较旧版本下降 70% 以上，且保留全部 Route、ViewModel 接口与 Data Class。
   * 运行 f -s <module>：仅输出该模块的骨架。
 * 健壮性验证：
   * 在非 Git 目录下运行不报错，能正常回退到 find。
   * 遇到文件名包含空格或特殊字符能正确处理（IFS= read -r）。
 * 输出规范：
   * 控制台输出清晰的彩色统计面板：文件数、总行数、体积（KB）、输出路径。
