# 《焚诀·Git 工作流》新手指南

> 本指南面向**完全不会 Git 指令**的用户。你不需要背任何命令，
> 只需要认识十几个「短指令」就够了。所有操作都有中文提示和确认，
> 不会的照着问号填就行。

---

## 一、这个工具包的初心

让不会 Git 的人也能安全地：

- **保存代码**（推送到云端，手机/电脑都有备份）
- **多设备同步**（今天手机写，明天电脑接着写）
- **多平台托管**（GitHub / GitLab / Gitee 码云 / 腾讯云 CNB / CODING）

它的设计原则是：

1. **绝不自动动你的代码**——所有会修改代码的操作（合并、覆盖、强推）
   都会先停下来问你，你确认了才执行。
2. **被拒绝时告诉你为什么**——推送失败不再是冷冰冰的 `❌ 推送失败！`，
   而是告诉你"远程有新提交，你落后了 N 个"，并给出可选方案。
3. **全中文、全交互**——方向键选菜单，回车确认，不用背指令。

## 二、场景问答：遇到问题怎么办

### Q1：我推送到一半被拒绝，提示"远程有 N 个新提交"？

这是最常见的情况：**你昨天推送后，远程流水线/定时任务自动产生了新提交**，
而你本地还是昨天的版本。

工具会自动检测到并显示：

```
⚠️  本地落后远程 3 个提交（远程可能有流水线/定时任务自动提交）

  📜 远程新增提交:
    a1b2c3 ⚡ update: 09-20 03:00
  📄 这些提交涉及的文件:
    M  fz-tools/fzgit.sh
  💡 你本地还有 5 个文件的未提交改动
```

三个选项怎么选：

| 选项 | 含义 | 什么时候选 |
|------|------|-----------|
| `[1]` 先拉取合并再推送 | 把远程的新内容下载下来，和你的合并后一起推 | **推荐**。远程的改动和你的不冲突时 |
| `[2]` 强制推送 | 用你本地的版本**覆盖**远程 | 你确定远程那几个新提交不要了（比如只是流水线自动提交） |
| `[3]` 取消 | 什么都不动，自己慢慢看 | 不确定的时候，先执行 `st` 或 `info` 查看状态 |

> 💡 **不用担心丢代码**：选 [1] 拉取合并时，你**已经推过的代码**不会丢。
> 只有"你正在改但还没推送"的文件，如果和远程改的是**同一个文件的同一处**，
> 才会产生冲突，工具会引导你解决（见 Q2）。

### Q2：提示有冲突了，怎么解决？

冲突 = 远程和本地改了**同一个文件的同一处**，Git 不知道听谁的。

1. 执行 `fix`，工具会列出所有冲突文件
2. 打开文件，找到这样的标记：

   ```
   <<<<<<< HEAD
   你本地的代码
   =======
   远程的代码
   >>>>>>> a1b2c3
   ```

3. **保留你要的那份**，把 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记删掉
4. 执行 `p` 重新推送即可

### Q3：我想推送到腾讯云 CNB / Gitee / GitLab，而不是 GitHub？

不需要去问 AI 要指令了。执行 `remote`：

```
🔗 远程仓库管理
当前远程地址:
  origin  https://github.com/xxx/xxx.git
识别平台: GitHub

  1. 设置/修改 origin（可选平台模板快速生成）
  2. 添加新的远程
  ...
```

选 `[1]`，然后会出现平台选择菜单（↑/↓ + 回车）：

```
选择推送平台:
  ❯ GitHub
    GitLab
    Gitee（码云）
    腾讯云 CNB
    CODING（腾讯）
    自定义（直接输入完整 URL）
```

选平台 → 输入用户名/组织名 → 输入仓库名，URL 自动拼好。

> 💡 **HTTPS 推送需要令牌**（密码）：各平台生成入口
> - GitHub：`https://github.com/settings/tokens`（或直接用 `login` 指令）
> - Gitee：设置 → 私人令牌
> - 腾讯云 CNB：设置 → 访问令牌
> - GitLab：Settings → Access Tokens（勾选 write_repository）
> - CODING：个人设置 → 访问令牌
>
> 推送时如果让你输密码，粘贴的就是这个令牌，不是登录密码。

想**同时保留 GitHub 和 CNB 两个远程**？选 `[2]` 添加新远程，
起个名字（比如 `cnb`），之后：

- `p` → 推 origin（GitHub）
- `git push cnb 分支名` → 推到 CNB
（跨平台多推正在计划中，当前版本一条指令推一个远程）

### Q4：我在手机上（Termux）用，换电脑了还能用吗？

**能。** 脚本是标准 bash + git，电脑上（Windows 用 Git Bash / WSL，
macOS / Linux 自带终端）都能跑。

电脑上安装：

```bash
git clone https://github.com/zzgs219G/scripts.git
echo 'source ~/scripts/fz-tools/fzgit.sh' >> ~/.bashrc
source ~/.bashrc
```

依赖也只有 git（可选 gh、curl）。手机和电脑的书签是各自独立的
（书签文件在各自的 HOME 下），第一次在电脑上执行 `c` 时会引导你
创建书签，指向你 clone 到本地的项目目录即可。

**注意**：手机上项目放在 `/storage/emulated/0/...`（手机存储），
电脑上没这个路径，脚本已做适配——检测不到手机存储时自动回退到
`~/repos`，不会报错。

### Q5：我不小心把不想提交的东西提交了怎么办？

- 还没推送：`no` 撤回最后一次提交（代码还在，只是取消这次提交记录）
- 已经推送：`git revert HEAD` 生成一条"反向提交"把内容抵消掉
  （不要用强推去"抹掉"，除非你确定没人基于这个提交干活）

### Q6：书签是什么？为什么我执行 c 问我书签？

书签 = 一个**顶层目录**。它下面的每个子文件夹都会被当作一个项目。
比如你把所有代码仓库都放在 `~/repos` 下，就把 `~/repos` 加成书签，
之后执行 `c` 就能列出里面所有项目，↑/↓ 选中直接进去。

## 三、指令速查（高频 10 个）

| 指令 | 作用 |
|------|------|
| `c` | 项目导航（书签→项目→进入，↑/↓ + 回车选择） |
| `st` | 看当前状态（分支 / 改动数 / 领先落后远程几个提交） |
| `p` | 一键推送（自动检测远程新提交防冲突） |
| `pull` | 拉取远程最新（保护未提交改动） |
| `save` / `pop` | 暂存当前改动 / 恢复暂存（切分支前保护现场） |
| `b` | 切换分支（列表选择） |
| `fix` | 冲突解决引导 |
| `remote` | 多平台远程管理 |
| `info` | 仓库完整信息 |
| `h` | 全部指令帮助菜单 |

## 四、一图看懂推送防冲突

```
        你执行 p
           │
           ▼
     git fetch（只下载信息，不动你的代码）
           │
     本地落后远程吗？
       ┌───┴───┐
      否        是
       │        │
    正常推送   ⚠️ 提醒：远程多了哪些提交、动了哪些文件
              + 你本地有多少没提交的改动
                │
        ┌───────┼────────┐
      [1]拉取  [2]强推  [3]取消
        │        │         │
    合并后推送  --force-  什么都不动
              with-lease
              （二次确认）
```

任何一步你都可以选取消，然后用 `st` / `info` / `lg` 看清楚再决定。
