一、设计哲学与总体架构

1.1 核心思想

· 项目位置无关性：项目可以散落在设备任何位置，工作台仅通过「书签」记录顶层目录。
· 操作即交互：所有常用指令（c, cl, pullall 等）默认进入交互菜单，无需记忆复杂参数。
· 移动即收纳：项目可在书签之间自由移动/复制，并自动修复 Git 安全权限。
· 上下文感知：命令能识别当前所在项目，提供更智能的默认行为。

1.2 总体架构

```
fz-tools/
├── fzgit.sh          (主入口，加载所有模块)
├── core.sh           (基础工具，保持不变)
├── modules/
│   ├── bookmark.sh   (新增) 书签管理（增删改查）
│   ├── nav.sh        (重构) 智能导航与项目操作
│   ├── clone.sh      (新增) 克隆增强（交互式选择）
│   ├── pullall.sh    (新增) 批量拉取（基于书签）
│   ├── branch.sh     (小幅增强) 分支操作
│   ├── push.sh       (小幅增强) 推送提示
│   ├── merge.sh      (保持不变)
│   ├── view.sh       (保持不变)
│   ├── burn.sh       (调整输出路径)
│   └── ... (其余模块)
```

三、c 命令的完全重写（modules/nav.sh）

3.1 交互流程（状态机）

阶段1：书签选择

```
$ c
📂 工作台书签（可用 bookmark 管理）：
  [1] 📁 克隆仓库     (/storage/...)
  [2] 📁 编译软件     (/storage/...)
  [3] ➕ 添加新书签
  [q] 退出
请选择编号或操作: 
```

· 选编号 → 进入该书签目录（cd）
· 选 3 → 引导添加新书签（名称+路径），添加后回到此列表
· 选 q → 退出，不改变目录

阶段2：项目列表（进入书签目录后）

```
📁 当前目录：克隆仓库
  [0] 📂 进入此目录（不选项目）   ← 新增！直接 cd 到书签根目录并结束
  [1] MyApp
  [2] NestBackend
  [3] scripts
  [b] 返回书签选择
  [q] 退出（停留在当前目录）    ← 按 q 等同于选 [0]
请选择编号: 
```

· 选 0 或 q → cd 到当前书签根目录，命令结束（用户停留在该目录）
· 选项目编号 → 进入项目操作菜单（阶段3）
· 选 b → 返回书签选择（cd 回原目录？实际上我们不需要回退目录，只需重新显示书签列表，但 cd 状态保留在书签根目录，因为交互是在 subshell 中？我们需要在父 shell 中切换目录，所以每个 cd 必须是有效的。设计：在显示列表前先 cd 到该书签目录，所以 b 返回时我们留在该书签目录，再次显示书签列表，但此时 pwd 是书签根目录。这没关系，因为书签选择本身不改变目录，只有当选择项目进入或移动后才切换。所以 b 只是重绘菜单，不额外 cd。）

阶段3：项目操作菜单

```
选中项目：NestBackend
你想做什么？
  [1] 进入该项目（cd 并结束）
  [2] 📦 移动本项目到其他书签（剪切）
  [3] 📋 复制本项目到其他书签（保留原件）
  [q] 取消
请选择: 
```

· 选 1 → cd 到项目路径，命令结束
· 选 2 或 3 → 显示目标书签列表（排除当前书签），选择目标书签后执行移动/复制操作，自动处理 safe.directory，然后 cd 到目标路径（若是移动）或留在原处（若是复制，可选择是否进入副本），默认移动后进入，复制后可选择是否进入副本。

3.2 移动/复制细节

· 冲突处理：若目标已存在同名目录，提示用户选择：覆盖 / 重命名（加 _副本） / 取消。
· 移动后自动执行 git config --global --add safe.directory 新路径。
· 移动后自动更新远端 remote（若有）无需额外操作。

3.3 辅助功能

· 添加书签快捷键：在阶段1选 3，或单独使用 bookmark add。
· 模糊搜索：在项目列表界面输入部分关键字可过滤（可选，初期可不实现）。

四、cl 命令增强（新增 modules/clone.sh）

4.1 交互式克隆

· 无参数执行 cl：
  1. 检查 gh 是否可用，若不可用则提示安装并退出。
  2. 调用 gh repo list --json name,url --jq '.[] | "\(.name)|\(.url)"' 获取仓库列表。
  3. 显示编号、仓库名，让用户选择。
  4. 选择后，询问目标目录（默认当前终端所在目录 pwd，也可选择书签目录）。
  5. 执行 git clone <url> <目标目录>/<仓库名>。
  6. 克隆完成后，自动将新项目路径添加到当前书签（若克隆到某书签下，则自动识别；若克隆到其他位置，可选择是否加入书签）。
· 带参数 cl <仓库名或URL>：直接克隆到当前目录（或指定书签），自动注册。

4.2 智能提示

· 克隆完成后，提示“是否立即进入该项目？(y/n)”，若选 y 则 cd 进入。

五、pullall 命令重构（新增 modules/pullall.sh）

5.1 批量拉取逻辑

· 遍历所有书签目录下的一级子目录（每个子目录视为一个项目，检查是否含 .git）。
· 对每个项目执行 git pull --quiet，显示进度和结果。
· 跳过非 Git 目录，并统计成功/失败数。
· 可选：指定书签名称，只更新该书签下的项目（pullall 编译软件）。

5.2 交互式增强

· 执行前显示“将更新以下书签下的所有项目：1.克隆仓库 2.编译软件”，确认后执行。
· 若某个项目拉取失败，记录并最后显示错误列表。

八、风险控制与测试

8.1 风险点

· 移动操作误删：移动前必须二次确认，并提供“取消”选项。
· 书签路径无效：若书签指向的目录被删除，在列表显示时标记 [失效]，选择后提示并可选移除。
· gh 未安装：cl 交互式列表依赖 gh，若未安装则降级为手动输入 URL。

8.2 测试用例

1. 首次执行 c，自动进入书签创建向导。
2. 添加两个书签，分别包含项目。
3. 在项目列表选择项目，进入、移动、复制操作验证。
4. cl 无参数列出 GitHub 仓库，克隆后自动识别书签。
5. pullall 更新所有项目，模拟网络失败处理。
6. 移动项目后检查 safe.directory 是否自动添加。
